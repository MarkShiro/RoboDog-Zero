# Orange Pi AIpro 8T: первый запуск и программная часть RoboDog

Целевая система: образ владельца `opiaipro_openEuler22.03_desktop_aarch64_20240604`. Эта инструкция написана для **полного комплекта с концевиками**. Orange Pi отвечает за Bluetooth-мост, приём телеметрии и IMU, сенсорное меню и адаптер LiDAR. Mega самостоятельно управляет STEP/DIR, поиском нулей, ограничениями и остановкой при потере команд. Никакой код на Orange Pi не был запущен на плате владельца: номера устройств, SPI-контроллер, GPIO и формат пакетов Coin D6 требуется подтвердить на железе.

## Порядок первого включения

1. Поставьте Orange Pi на изолирующую поверхность с охлаждением. Питайте её штатным для **вашей ревизии AIpro 8T** источником, проверенным по напряжению, полярности и работе под нагрузкой. Не подключайте 8S батарею к GPIO или USB. В этот момент Mega и силовые драйверы отключены.
2. Подключите монитор/клавиатуру и сеть. В терминале Orange Pi проверьте:

   ```bash
   cat /etc/os-release
   uname -m
   uname -r
   python3 --version
   ip -br addr
   systemctl --failed
   journalctl -b -p err --no-pager -n 50
   ```

   Ожидаются `aarch64` и openEuler. Сохраните результаты в свой журнал. Для проверки Ascend/NPU отдельно выполните `command -v npu-smi` и, если найдено, `npu-smi info`; эта программа NPU пока не использует.
3. Задайте свой пароль (`passwd`), проверьте доступ по SSH (`systemctl status sshd`). Не меняйте сетевые настройки, не сделав снимок системного носителя. Образ и пароль не кладите в GitHub.
4. Проверьте штатные репозитории: `sudo dnf repolist`. Если чего-то нет, установите из репозитория образа `git`, `python3-pip`, `bluez`, `libgpiod` и утилиты SPI по доступным именам. Не используйте команды `apt` на openEuler.

## Установка проекта

```bash
cd ~
git clone https://github.com/MarkShiro/RoboDog-Zero.git robodog
cd ~/robodog/orange_pi
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
cp config.example.json config.json
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python -m robodog.app --config config.json --demo --snapshot --page 0
./.venv/bin/python -m robodog.app --config config.json --demo --snapshot --page 1
./.venv/bin/python -m robodog.app --config config.json --demo --snapshot --page 2
```

Это создаст `screen-preview.png` для каждой страницы по очереди. В `--demo` IMU и лидар **искусственные** и помечены как демонстрация. Откройте PNG обычной программой просмотра. Пуск без `--demo` не разрешает моторы. `config.json` содержит адреса ваших локальных устройств и оставлен вне Git.

`requirements.txt`: Pillow рисует меню, pyserial работает с Mega/лидаром, python-periphery обращается к SPI и GPIO через Linux character devices. При проблеме установки проверьте версию Python и наличие системных заголовков/библиотек образа; не заменяйте системный Python и Ascend. Для фоновой работы сначала пройдите ручной запуск и отдельные проверки каждого интерфейса.

## Связь Mega ↔ Orange Pi

Схема использует `Serial3` Mega, 38400 8N1: Mega D14/TX3 → RX Orange Pi **через проверенный делитель 5→3,3 В**, Mega D15/RX3 ← TX Orange Pi, общий GND. Если вместо GPIO-UART используется отдельный USB–TTL 3,3 В адаптер, его порт будет `/dev/ttyUSB*` либо `/dev/serial/by-id/*`. Не путайте с USB-переходником лидара: это два разных последовательных соединения. Для первого теста можно использовать проверенный USB–TTL и позже перейти на штатную проводку схемы.

На Orange Pi найдите порт после подключения:

```bash
ls -l /dev/serial/by-id 2>/dev/null
ls -l /dev/ttyUSB* /dev/ttyACM* /dev/ttyAMA* 2>/dev/null
sudo dmesg | tail -n 40
id
```

Не угадывайте `/dev/ttyUSB0`: порядок устройств меняется. Укажите подтверждённый путь в `mega_port` `config.json`. Для GPIO-UART сверяйте 40-pin распиновку **именно AIpro 8T** и занятые консолью интерфейсы. Перед двусторонним подключением измерьте уровни сигналов. Чтение `T,seq,state,vbusMv,flags*CRC` (около 10 Гц), `I,roll,pitch,temp,flags*CRC` (около 5 Гц) и `X*CRC` можно проверять с отключённой силовой частью. Контрольная сумма CRC-8/0x07 проверяет ошибки передачи, но не подтверждает личность отправителя.

## Пульт HC-05 по Bluetooth Classic

Пульт передаёт `C,seq,buttonsHex,remoteMv,speed,mode*CRC\n` каждые 50 мс через HC-05 на 38400. На Orange Pi включите Bluetooth, найдите MAC своего HC-05 и выполните сопряжение через `bluetoothctl`. PIN берите из настроек конкретного модуля; типовые значения не считаются подтверждёнными. Найдите его RFCOMM/SPP channel в SDP (`sdptool browse <MAC>`, если утилита доступна). Запишите `hc05_mac` и `hc05_rfcomm_channel` в `config.json`.

Приложение держит одно RFCOMM-соединение с HC-05, принимает только новые корректные seq и пересылает оригинальные кадры Mega. Оно **не повторяет старую команду движения** после потери связи. Mega сама выключает драйверы по тайм-ауту. Телеметрия `T` идёт обратно пульту. Пароль сопряжения Bluetooth и доступ к локальному пользователю Orange Pi — часть защиты радиоканала; CRC не является шифрованием или аутентификацией.

Сначала протестируйте движение команд в телеметрии при отключённых моторах. Только после заполнения калибровки Mega, проверки всех концевиков, тока, напряжений и физического аварийного разрыва выполняйте отдельный запрос разрешения:

```bash
./.venv/bin/python -m robodog.app --config config.json --arm
```

Команда обращается к локальному Unix-сокету с правами владельца, но ответ `REQUESTED` означает **постановку запроса в очередь**, а не успешный ARM. Приложение отправит `A,seq*CRC` только при свежем нейтральном пульте и свежей безопасной телеметрии. Окончательное решение принимает Mega; проверяйте её `STATUS` и флаги. Сам запуск приложения никогда не отправляет ARM. Доступ к Orange Pi и сервису должен иметь только оператор.

## Экран 2,4″ TFT SPI 240×320 с касанием

Фото задней стороны модуля владельца показывает надпись **2.4″ TFT SPI 240X320 V1.3**, а не ранее предполагаемые 2,8″. На гребёнке обозначены `T_IRQ`, `T_DO`, `T_DIN`, `T_CS`, `T_CLK`, `SDO(MISO)`, `LED`, `SCK`, `SDI(MOSI)`, `DC`, `RESET`, `CS`, `GND`, `VCC`; справа есть отдельные выводы SD. Экран робота установлен **вертикально**: программа создаёт изображение **240×320**; первая страница — крупная надпись **ZE / RO** в две строки, а в нижнем меню находятся **ZERO**, **IMU**, **ЛИДАР**. Контроллер TFT (ST7789 либо ILI9341), контроллер касания (предположительно XPT2046) и реальное питающее напряжение модуля **не подтверждены по фото**. Сначала сверьте маркировку микросхем или документацию продавца; выставляйте 3,3/5 В только согласно реальному модулю и уровневым преобразователям.

На Linux нужны два аппаратных SPI chip-select: `spi_display` для `CS`, `spi_touch` для `T_CS`; линии MOSI/MISO/SCK общие. Выходы `DC` и `RESET`, вход `T_IRQ` идут на три GPIO. `LED` (подсветка) и `VCC` — отдельные электрические цепи; программа их не запитывает. SD-карту программа не использует. Физические контакты Orange Pi берите из вашей схемы, а номера GPIO chip/offset — из активной конфигурации openEuler, **не из номера контакта гребёнки**.

```bash
ls -l /dev/spidev* /dev/gpiochip* 2>/dev/null
gpioinfo | less
sudo dmesg | grep -Ei 'spi|gpio' | tail -n 40
```

Если `/dev/spidev*` нет, включите SPI/pinmux методом, документированным для **вашего образа AIpro 8T**; не копируйте overlay от Orange Pi 5 или Raspberry Pi. Запишите в `config.json` два пути SPI, `/dev/gpiochipN`, смещения линий `DC/RESET/T_IRQ`, `controller`=`st7789` или `ili9341`, затем переключите `ui_backend` с `png` на `spi`. В конфигурации должны стоять `width=240`, `height=320`; старые настройки 320×240 отвергаются. `madctl=null` выбирает начальный портретный режим контроллера (`0x00` для ST7789, `0x48` для ILI9341); если конкретный модуль показывает перевёрнутую или зеркальную картинку, подберите и сохраните его `madctl`, затем отдельно калибруйте оси касания. Сначала запустите однокадровую проверку `--demo --snapshot` и убедитесь, что **ZE сверху, RO снизу, меню вдоль нижней короткой стороны**. При неверных цветах/повороте подбирайте `madctl` и `x_offset/y_offset` по тестовому изображению, записывая результаты. Если один из двух контроллеров не даёт осмысленной картинки, верните питание/провода к исходному состоянию и проверьте маркировку контроллера.

Для касания положите палец в четыре угла и выполните:

```bash
./.venv/bin/python -m robodog.app --config config.json --probe-touch
```

Значения `touch raw x/y` помогут установить `touch_x_min/max`, `touch_y_min/max`, `touch_swap_xy`, `touch_invert_x/y`. После калибровки попробуйте все три нижние кнопки. Касание **меняет страницу**, но не запускает моторы. Экран IMU показывает данные Mega и сообщает об их отсутствии/устаревании; экран лидара не подменяет реальные данные демонстрацией в штатном режиме.

## Coin D6 по комплектному переходнику USB–UART

Указанный [товар Coin D6](https://rcdrone.top/products/witmotion-dtof-lidar) сообщает UART 230400 бод и комплектный USB–UART адаптер. Датчик подключается к Orange Pi через этот адаптер; GPIO UART для лидара не нужен. Найдите его отдельный `/dev/serial/by-id/*` и укажите в `lidar.usb_port` `config.json`. Батарею или питание моторов к нему не подключать: питание датчика и переходника должно соответствовать их маркировке.

```bash
ls -l /dev/serial/by-id 2>/dev/null
./.venv/bin/python -m robodog.app --config config.json --capture-lidar ~/coin-d6-sample.bin --seconds 5
wc -c ~/coin-d6-sample.bin
```

Запись сохраняет не более 2 МБ сырых байтов и по умолчанию ничего датчику не посылает. Если файл пуст, это ещё не доказывает неисправность: по [открытому ROS-драйверу COIN-D6 / CSPC TOF](https://github.com/sachisti/OnStage26/tree/main/support/original_coind6_ros_module) поток запускается четырёхбайтовой командой. Повторите запись с `--lidar-start`: эта опция после открытия порта посылает `AA 55 F0 0F`, затем записывает поток. Архив `Witmotion(V2025.11.26.0)` из присланной ссылки содержит универсальную программу и DLL, но в нём не найдено явной спецификации COIN-D6. Не применяйте к D6 общий IMU-протокол WitMotion или драйвер другой модели D6.

В проект добавлен **прямой декодер** `coin_d6.py`: он ищет кадры TOF из открытого SDK, проверяет его XOR-контрольную сумму, 8-битное число точек, начальный/конечный угол, разбирает расстояние в миллиметрах и собирает оборот. Для реального режима поставьте `lidar.source="coin_d6"`, `lidar.usb_port` и 230400 бод. `send_start_command=true` посылает после открытия порта команду запуска из SDK `AA 55 F0 0F`. Сначала держите робот на месте и проверьте, что на экране окружность меняется, когда перед датчиком перемещается предмет на измеренном расстоянии; сопоставьте поворот и дальность. Декодер испытан на синтетическом кадре, но **не на байтах вашего датчика**. При несовпадении прошивки/протокола экран честно сообщает, что корректных пакетов нет; сохраните сырой поток и уточните у продавца SDK своей ревизии.

Альтернативно внешний проверенный SDK может писать JSON-lines: одна строка `{"points":[[угол_в_градусах,дальность_в_метрах],...]}` на скан. Для него поставьте `lidar.source="jsonl"` и `lidar.jsonl_path`. Диапазоны и свежесть точек проверяются. Без корректных пакетов реальный экран показывает «Нет подтверждённого скана»; деморежим показывает синтетический контур с надписью «ДЕМО».

## Запуск и выключение

После проверки отдельных цепей запустите в терминале:

```bash
cd ~/robodog/orange_pi
./.venv/bin/python -m robodog.app --config config.json
```

`Ctrl+C` завершает потоки и закрывает интерфейсы. Для фонового запуска сначала проверьте реальное имя пользователя, группы доступа к tty/SPI/GPIO и локальные пути, затем создайте собственный unit `systemd` с `ExecStart=/путь/к/venv/bin/python -m robodog.app --config /путь/config.json`, `WorkingDirectory=/путь/orange_pi`, `User=<пользователь>`, `Restart=on-failure`. Проверьте его `systemd-analyze verify`, ручной `systemctl start/stop`, журнал и перезагрузку. Самозапуск не должен ARM. Автоматическое выключение питания по сообщению Mega `X` пока **не реализовано**: программа показывает предупреждение, оператор завершает `sudo systemctl poweroff` и снимает питание по проверенной схеме. Не оставляйте батарею в разряжающемся режиме ожидания.

## Что ещё требуется измерить для первого шага

- На Mega: карту J1–J8, знаки углов, направление и положение всех восьми концевиков, рабочие пределы и позы, фактическую работу силового аварийного отключения, уровни АЦП, Rsense и нагрев драйверов.
- На Orange Pi: имена двух UART/USB устройств, MAC и канал HC-05, доступность SPI0/CS0/CS1, GPIO offsets, точный контроллер TFT и калибровку касания.
- Для LiDAR: подтвердить на живом датчике совместимость его прошивки с пакетами открытого SDK и измерением реального препятствия. Наличие `/dev/ttyUSB*` доказывает только связь с USB-переходником, а не правильный скан.

Пока эти измерения не выполнены, код компилируется и демонстрирует меню, но выпускать робота на самостоятельную ходьбу нельзя. Рысь в Mega остаётся отдельно выключенной до проверки кинематики и устойчивости.
