# Настройка восьми концевиков: любой порядок проводов и NO/NC

Эта инструкция отделяет **физический вход Mega D42–D49** от **сустава J1–J8**. Разъёмы могли оказаться переставлены, поэтому итоговая прошивка не предполагает, что J1 обязательно использует D42. Каждый сустав должен иметь собственный исправный датчик, который срабатывает **до** механического упора. Программа может исправить перестановку исправных входов D42–D49, но не обрыв, замыкание, неверное напряжение или датчик на другом пине.

## 1. Сначала электрическая проверка, без движения

1. Поднимите корпус на жёсткую опору. Выключите питание моторов, отключите Orange Pi от цепи управления Mega. Оставьте USB Mega и концевики. Не нажимайте рукой на движущуюся ногу.
2. Убедитесь по схеме своего экземпляра, что одна сторона каждого **сухого контакта** идёт на GND Mega, другая — на один вход D42–D49. Код включает `INPUT_PULLUP`; подавать на эти входы 5 В/напряжение батареи от внешнего датчика нельзя. Для трёхпроводного активного датчика нужна отдельная схема согласования уровней; не подключайте его по инструкции для сухого контакта.
3. Загрузите `firmware/RoboDogMotorMap/RoboDogMotorMap.ino`. Монитор порта: 115200, конец строки `Newline`. Команда `STATUS` доступна без `SCAN`, `ARM` и питания моторов. Она печатает восемь **raw** битов: позиция 1 = D42, позиция 8 = D49; `1` означает HIGH.
4. Запишите восемь raw битов, когда все датчики отпущены. Медленно нажмите **один физический датчик** рукой, снова отправьте `STATUS`, отпустите и повторите. Должен измениться ровно один бит, затем вернуться к исходному значению. Повторите 3–5 раз для каждого датчика. Записывайте фактический пин, а не номер предполагаемого разъёма на плате.

| Соединение сухого контакта с GND | Отпущен | Нажат | `limit_pressed_level` |
|---|---|---|---|
| NO, нормально разомкнутый | HIGH (`1`) | LOW (`0`) | `LOW` |
| NC, нормально замкнутый | LOW (`0`) | HIGH (`1`) | `HIGH` |

Для NC при обрыве провод обычно даст HIGH и будет распознан как нажатие. Для NO обрыв выглядит как «отпущен», поэтому ежедневная проверка нажатия особенно важна. Полярность можно смешивать: на каждом входе она настраивается отдельно. Если исходные биты неустойчивы, измерьте контакт мультиметром и проверьте общий GND, подтяжку, разъём и прокладку вдали от силовых кабелей. При одном нажатии меняются два бита — ищите замыкание. Не меняется ни один — обрыв, неверный пин или неисправный контакт. Меняется чужой пин — это допустимая перестановка, если датчик **единственный** на этом входе; запишите реальный номер.

## 2. Сопоставьте датчик с мотором

Порядок J определяется короткими командами `J1`…`J8` в стендовой прошивке. Для каждого J сначала установите, какую **ногу и сустав** он двигает, и найдите датчик, физически ограничивающий именно этот сустав. Нельзя назначить ближайший датчик по месту разъёма: выключите моторы, нажмите конкретный контакт и сверьте D-пин в таблице. На каждого J должен приходиться один уникальный D42–D49; каждый D-пин используется ровно раз.

В стендовой прошивке `LIMIT_ACTIVE_LOW[8]` соответствует **физическим входам** D42–D49. До `ARM` задайте `true` для NO/LOW и `false` для NC/HIGH по таблице; заново загрузите скетч. Теперь `STATUS` показывает вторую строку `pressed` (1 = сработал по выбранной полярности). С отпущенными датчиками должны быть восемь нулей, при одном нажатии — ровно одна единица. Стенд блокирует одиночное перемещение при любом нажатом датчике. Эта проверка не заменяет аппаратный аварийный разрыв питания.

## 3. Запишите данные в профиль итоговой прошивки

Создайте локальный бланк из корня репозитория:

```bash
python tools/generate_calibration.py --init commissioning/robot.json
```

Этот файл исключён из Git: он содержит измерения **конкретного** экземпляра. В массиве `axes` строки всегда идут J1…J8. В каждой строке укажите `limit_pin` (полное число 42–49) и `limit_pressed_level` (`LOW` или `HIGH`). Например, если датчик J1 фактически попал на D43, а J2 — на D42, поставьте соответственно `43` и `42`: провода можно оставить на месте после подтверждения целостности обоих входов. Генератор преобразует их в `LIMIT_INPUT_FOR_J = {1,0,...}`; `motion.cpp` читает нужный физический вход для каждого J. Дубликаты и пины вне D42–D49 отклоняются.

После заполнения **всей** карты осей и измеренных углов выполните:

```bash
python tools/generate_calibration.py --input commissioning/robot.json
```

Команда проверяет профиль и создаёт `firmware/RoboDogMegaFinal/calibration.h` с **заблокированным ARM**. Сначала загрузите его так, чтобы `STATUS` показывал `calibrated=0` и строку `limits J1..J8` — все нули в отпущенном состоянии; при ручном нажатии Jn меняется только n-й бит. Проверяйте по очереди все восемь. Это вторая, логическая проверка после raw-проверки. Не переходите к `--unlock`, пока совпадение не полное.

## 4. Проверьте направление поиска и рабочую зону

Концевик — физическая граница. `home_dir` = `+1` или `-1` означает электрическое направление **к** датчику, определённое коротким одиночным jog с поддержанной ногой. `angle_sign` — знак изменения измеряемого угла при положительном электрическом STEP. Оба знака измеряются отдельно; нельзя выводить один из другого только по схеме. Точка срабатывания `home_angle_deg` и границы `min_angle_deg`/`max_angle_deg` задаются для **того же** измеряемого суставного угла. Обе рабочие границы должны лежать по сторону отхода от датчика, а программный отход на 200 микрошагов должен попасть внутрь этого интервала. `max_home_steps` ограничивает путь поиска; не ставьте произвольный максимум вместо замера безопасного хода.

Запуск поиска выполняйте, когда **все восемь датчиков отпущены**, ноги поддержаны, аварийная кнопка доступна. Прошивка двигает по одной оси и прекращает поиск, если во время поиска сработает датчик другой оси, превышено время/число шагов или после отхода контакт остался активным. Если датчик не размыкается при отходе, выясните причину до следующего запуска. Проверка ПО не доказывает, что механизм не упрётся раньше: сравните направление и запас хода вручную с отключённым питанием.

Ежедневный контроль перед запуском: при отключённых моторах отпустить все датчики, убедиться в нулях `STATUS`, вручную нажать и отпустить каждый, проверить индивидуальное срабатывание, затем испытать аппаратную аварийную кнопку. После любого ремонта проводки повторить raw- и логическую проверку полностью.
